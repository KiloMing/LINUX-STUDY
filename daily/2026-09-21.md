## 今日真正掌握

### CMake 基础

- CMake 不是编译器；它读取 `CMakeLists.txt` 生成构建系统，真正编译仍由 gcc/g++ 等工具完成。
- `add_executable(target source...)` 的第一个参数是 target / 最终 executable 名，后面是组成该程序的源文件。
- 多个 `.cpp` 放进同一个 `add_executable()` 是“多个源文件组成一个程序”，不是“同时运行多个文件”；程序仍从唯一 `main()` 入口开始。
- 如果希望每个 `.cpp` 生成独立 executable，就分别写多个 `add_executable()`，并让每个独立程序有自己的 `main()`。
- `cmake -S . -B build` 是 configure/generate，`cmake --build build` 才是真正编译。
- `cmake .` 会把当前源码目录同时当 build tree，属于 in-source build；会生成 `CMakeFiles/`、`CMakeCache.txt`、`Makefile`、`cmake_install.cmake` 等中间文件。正式工程优先 out-of-source build。
- `find_package(rclcpp REQUIRED)` 负责查找依赖包；`target_link_libraries()` 或 ROS2 的 `ament_target_dependencies()` 负责把依赖交给具体 target。

### ROS2 构建链

- workspace 是更高层的工作空间，可以包含多个 package；package 是 ROS2 的基本工程组织单位。
- `ros2 pkg create --build-type ament_cmake ...` 会生成 `package.xml`、`CMakeLists.txt`、`src/`、`include/` 等 package 骨架。
- ROS2 CMake 最小骨架：`find_package(ament_cmake REQUIRED)`、`find_package(rclcpp REQUIRED)`、`add_executable()`、`ament_target_dependencies()`、`install()`、`ament_package()`。
- `colcon` 是 workspace 级构建工具：扫描 package、按依赖顺序调用构建系统，并生成 `build/`、`install/`、`log/`。
- 编译后需要 `source install/setup.bash`，当前终端才会认识这个 workspace 的安装结果。
- `ros2 run <package> <executable>` 使用的是安装后的 executable 名，不是 `.cpp` 文件名。
- `ros2 pkg executables <package>` 可以检查某个 package 当前实际安装了哪些 executable。

### Linux / 工具操作补充

- 删除目录：空目录可 `rmdir`；含内容目录使用 `rm -r`，`rm -rf` 需谨慎。
- 移动/改名使用 `mv`。
- VS Code 使用内置 Auto Save 可避免 CMake 读取磁盘上的旧文件。

## 暴露的问题

1. CMakeLists 修改后忘记保存，终端仍读取旧内容，导致反复出现已经“看似修复”的错误。
2. 把 C/C++ 的分号习惯带进 CMake，产生 `Parse error`；CMake command 结尾不需要 `;`。
3. 写了 `ament_target_dependencies(cpp_node rclcpp)` 却没有先 `find_package(rclcpp REQUIRED)`，CMake 明确报依赖未找到。
4. `add_executable()` 中写的源文件路径和实际 `src/node.cpp` 不一致。
5. 直接 `cmake .` 把 build tree 混进源码目录；后续正式练习统一 out-of-source build。
6. `source install/setup.bash` 的位置取决于 colcon build 的 workspace 根目录；不能随意切目录后假设当前目录一定有 `install/`。
7. `ros2 run` 的第二个参数必须是当前安装结果中真实存在的 executable。修改 CMake target 后必须重新 build + source。

## 学习方向

正式主线进入 **CMake/C++ 工程化**，ROS2 先只做构建链预热。下一阶段按以下顺序推进：

```text
普通 CMake 闭卷复现
  → 多 target / include / library / find_package
  → 标准 ROS2 workspace 与 package
  → 最小 rclcpp node 的 build / install / source / run
  → topic publisher/subscriber
  → service
  → action
  → parameter / launch
```

Socket 不丢：poll/epoll LT、TCP 文件传输和短读写等既有验收继续作为 Linux/通信能力并行补证，但不再扩展成高并发服务器专项。
