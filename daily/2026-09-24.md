### 1. 复习 Timer、spin 与 Executor

今天先闭卷复习了 Timer。最初把 callback 理解为“创建后会自动执行”，随后纠正为：

```text
create_wall_timer()
    = 创建 Timer + 注册周期 + callback

rclcpp::spin(node)
    = 让 Executor 持续等待并调度就绪 callback
```

`rclcpp::TimerBase::SharedPtr timer_` 只是 Timer 句柄声明；真正创建 Timer 的是 `create_wall_timer()`。没有运行 Executor/Spin，Timer callback 不会仅靠“注册”自行执行。

### 3. Topic 名不一致实验

把订阅端 Topic 改为与发布端不同的名称（例如 `timer_topic` / `timer_opic`）后，程序本身仍可正常启动，但不会建立对应的数据流。

结论：Topic 是命名通信通道；Publisher 与 Subscription 需要解析后的 Topic 名和消息类型匹配，且 QoS 等条件兼容，才能实际通信。

### 5. CMake 链接错误与排查

第一次编译语音版 Subscription 时出现：

```text
undefined reference to espeak_Initialize
undefined reference to espeak_SetVoiceByName
undefined reference to espeak_Synth
undefined reference to espeak_Synchronize
...
```

该错误发生在链接阶段，不是 include path 问题。

学习到：

```cmake
find_library(ESPEAK_NG_LIBRARY NAMES espeak-ng REQUIRED)
```

只负责找到库的位置；还需要把库链接到实际 target：

```cmake
target_link_libraries(
  subscription
  ${ESPEAK_NG_LIBRARY}
)
```

同时理解了 `ament_target_dependencies(subscription rclcpp std_msgs)` 与 `target_link_libraries()` 的关系：二者功能有重叠，`ament_target_dependencies()` 是 ament/ROS2 依赖辅助宏，内部也可能参与 target 链接；espeak-ng 当前通过普通 CMake library 路径接入，因此使用 `target_link_libraries()`。

当前环境还触发了 plain/keyword signature 冲突：`ament_target_dependencies()` 已对 `subscription` 使用 plain 风格的 `target_link_libraries`，因此后续同一 target 不能再混用 `PRIVATE` keyword 风格。最终采用：

```cmake
target_link_libraries(
  subscription
  ${ESPEAK_NG_LIBRARY}
)
```

### 6. 发现 Subscription 语音 callback 的阻塞问题

语音输出虽然已经成功，但观察到当前程序表现为“读完一句后，才继续处理下一条 Subscription callback”。

更准确的模型是：

- Subscription 本身是事件驱动的；
- `rclcpp::spin(node)` 默认使用单线程 Executor；
- `espeak_Synchronize()` 是耗时阻塞操作；
- callback 未返回期间，该 Executor 线程无法执行下一次 Subscription callback。

因此“只能读完一句再接收”实际上是 **耗时 callback 阻塞单线程 Executor**。

### 7. 开始生产者-消费者解耦

今天已经进入下一版设计：

```text
ROS2 Executor / Subscription callback
        ↓
只负责 queue.push(msg->data)
        ↓
快速返回

std::queue<std::string>
        ↓

speech_thread
        ↓
queue.pop()
        ↓
espeak-ng
```

对应关系：

```text
Subscription callback = Producer
std::queue             = Buffer
speech_thread          = Consumer
```

实现需要：

- `std::queue<std::string>`
- `std::mutex`
- `std::condition_variable`
- `std::thread`

这样 `espeak_Synchronize()` 仍然可以阻塞语音工作线程，但不再阻塞 ROS2 Executor。
