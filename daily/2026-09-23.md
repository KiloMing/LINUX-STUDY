### 1. Node 内有哪些对象

```text
Node（逻辑节点，一个进程可以包含多个 Node）
├── Timer：周期到达后 callback 就绪
├── Publisher：publish(msg) 发布消息
└── Subscription：消息可用后 callback 就绪

Executor 在 spin 时调度就绪且可执行的 callback
Timer callback → Publisher → Topic → Subscription callback
```

`TimerNode` 和 `TimerPublisher` 都只是自定义 C++ 类名，没有 ROS2 预设的功能差异。一个类只包含 Timer，就可以只定时打印；类中同时包含 Timer 和 Publisher，并在 callback 中调用 publish，才实现定时发布。C++ 类名、`Node("节点名")`、CMake target 名和 Topic 名是不同概念。

Topic 是逻辑命名通信通道，不是一个独立转发进程或必须创建的服务器。`Publisher → Topic → Subscriber` 是通信模型；在 rclcpp 中具体创建的订阅对象叫 `Subscription`。通信要求解析后的 Topic 名、消息类型匹配，并且 QoS 兼容、发现及网络正常；名称相同不保证必然收到消息。

### 2. Timer 句柄与创建

```cpp
rclcpp::TimerBase::SharedPtr timer_;
```

这只是声明用于保存 Timer 的共享智能指针成员，初始为空；并未创建 Timer。真正创建并关联到当前 Node 的是：

```cpp
timer_ = this->create_wall_timer(
    1000ms,
    [this]() { timer_callback(); }
);
```

`create_wall_timer(period, callback)` 接收周期与可调用对象，返回 Timer 句柄。这里的 `1000ms` 需要 `<chrono>` 与 `using namespace std::chrono_literals;`。wall timer 使用稳定的时间基准，不跟随 ROS 仿真时间；周期到达表示可调度，不保证 callback 恰好在每个整秒执行。

`[this]` 捕获当前对象的指针，使 lambda 可以访问成员；`timer_callback()` 在此相当于 `this->timer_callback()`。捕获 this 不会复制整个对象，也不会自动延长对象生命周期。创建 lambda 时只是保存处理逻辑，不会立即调用函数。

### 3. spin 与 Executor

```cpp
rclcpp::spin(node);
```

在这个基础用法中，spin 使用单线程 Executor，把 node 加入执行器并持续处理事件。概念上对应：

```cpp
rclcpp::executors::SingleThreadedExecutor executor;
executor.add_node(node);
executor.spin();
```

Timer 到期、订阅消息可用等事件使 callback 就绪；Executor 再执行允许调度的 callback。Timer 不等于独立工作线程，callback 也不天然异步。单线程执行器里，耗时 callback 会延迟其他 callback。只创建节点和 Timer、却没有运行 Executor，不会自动执行这个 Timer callback。以上基础调度关系参考 [ROS2 官方 Executor 文档源码](https://github.com/ros2/ros2_documentation/blob/humble/source/Concepts/Intermediate/About-Executors.rst)。

### 4. 定时发布关键 C++ 示例

下面是按今日知识整理的教学示例，不是从实际工作区取回的原始源码，也未在本次环境中编译。

```cpp
#include <chrono>
#include <memory>
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

using namespace std::chrono_literals;

class TimerPublisher : public rclcpp::Node
{
public:
    TimerPublisher() : Node("timer_publisher")
    {
        publisher_ = this->create_publisher<std_msgs::msg::String>(
            "time_topic", 10);
        timer_ = this->create_wall_timer(
            1000ms, [this]() { timer_callback(); });
    }

private:
    void timer_callback()
    {
        std_msgs::msg::String msg;
        msg.data = "Hello ROS2";
        publisher_->publish(msg);
    }

    rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
    rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char **argv)
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<TimerPublisher>();
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

`std_msgs::msg::String` 是 ROS2 消息类型，其中 `data` 字段是 `std::string`。`publisher_->publish(msg)` 向创建 Publisher 时绑定的 `time_topic` 发布。这里演示周期发送字符串，Topic 名中的 time 不代表消息必须是时间戳。

### 5. Subscription 的结构与消息回调

基本形状：`create_subscription<MsgT>(topic, QoS, callback)`。以下成员片段应放在订阅节点类中：

```cpp
// 成员声明
rclcpp::Subscription<std_msgs::msg::String>::SharedPtr subscriber_;

// 在构造函数中创建
subscriber_ = this->create_subscription<std_msgs::msg::String>(
    "time_topic", 10,
    [this](std_msgs::msg::String::ConstSharedPtr msg)
    {
        subscriber_callback(msg);
    });

// 成员函数
void subscriber_callback(std_msgs::msg::String::ConstSharedPtr msg)
{
    RCLCPP_INFO(this->get_logger(), "Received: %s", msg->data.c_str());
}
```

模板参数指定消息类型；字符串指定 Topic；`10` 简写指定 KeepLast 历史深度，其余 QoS 使用默认策略，不表示十秒或十个订阅者；lambda 指定拿到消息后的处理逻辑。这里采用只读消息指针；课程中的 `const std_msgs::msg::String::SharedPtr msg` 只限制该指针变量本身被重新赋值，并不让它指向的消息成为 const。

| callback | 事件 | 本例参数 | 处理内容 |
|---|---|---|---|
| Timer callback | 时间到达 | 无参数 | 构造消息并发布 |
| Subscription callback | 消息可用 | 消息指针 msg | 读取 `msg->data` |

两种 callback 都由 Executor 调度。Publisher 的 publish 不等同于在发布函数栈中直接调用另一节点的订阅 callback。发布订阅基础用法参考 [ROS2 官方 C++ 教程源码](https://github.com/ros2/ros2_documentation/blob/humble/source/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Cpp-Publisher-And-Subscriber.rst)。

### 6. 今日 CMake 错误：download_file target 未定义

今日遇到 `ament_target_dependencies()` 第一个参数不是有效 target 的错误：调用时 `download_file` 尚未通过 `add_executable()` 或 `add_library()` 创建。它不是因为缺少名为 download_file 的 ROS 包，也不能只靠新增 `find_package(download_file)` 修复。[ament 宏源码](https://github.com/ament/ament_cmake/blob/humble/ament_cmake_target_dependencies/cmake/ament_target_dependencies.cmake) 会先检查 `if(NOT TARGET ...)`，之后才处理包依赖。

核对顺序：先看 target 是否存在、名称是否拼错、创建语句是否被注释或放在未进入的条件分支，再核对依赖与 install 列表。文件名不会自动创建同名 target。

以下是 **timer 部分的配置参考片段**，假定实际源文件为 `src/timer.cpp`，不能整段覆盖已有 CMakeLists.txt：

```cmake
find_package(ament_cmake REQUIRED)
find_package(rclcpp REQUIRED)
find_package(std_msgs REQUIRED)

add_executable(timer src/timer.cpp)
ament_target_dependencies(timer rclcpp std_msgs)

install(TARGETS timer
  DESTINATION lib/${PROJECT_NAME}
)

# 保留其他已存在 target、依赖、安装及测试配置。
# ament_package() 在完整文件末尾只保留一次。
```

同时检查 `package.xml` 含 `ament_cmake` 的构建工具依赖，以及 `rclcpp`、`std_msgs` 的依赖声明。若保留 download_file 功能，应使用真实源文件先创建该 target，再保留其实际依赖、include 路径和安装配置；不能为消除报错随意删除已有功能。`timer` 名称必须在创建、依赖绑定、安装与 `ros2 run demo_cpp_pkg timer` 中对应一致，源文件路径以真实工程为准。
