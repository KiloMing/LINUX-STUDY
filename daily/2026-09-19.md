## 今日学习内容（独立掌握待验证）

- **TCP 缓冲区：** 区分应用缓冲区与内核发送/接收缓冲区；send 成功返回只说明接受了相应字节，不证明对端应用已收到或文件已落盘。继续处理短读写与消息边界。
- **三次握手/四次挥手：** 学习连接建立、双向关闭与状态变化；“四次挥手”是典型流程，ACK 与 FIN 可以合并，不能机械认定抓包永远是四个包。
- **Nagle：** 理解小段合并、未确认数据与延迟 ACK 的相互影响；TCP_NODELAY 可禁用 Nagle，但不提供应用层消息边界。延迟 ACK 时间不是固定的 40 ms 常量。
- **listen：** 监听 fd 用于等待连接，accept 返回连接 fd。Linux 的 backlog 约束等待 accept 的已完成连接队列，并受系统上限限制；不能把教材“backlog + 1”当作通用接口契约。
- **select / bitmap / fd_set：** 用位图理解描述符集合，通过 FD_ZERO/FD_SET/FD_CLR/FD_ISSET 操作；每轮从长期集合复制工作集合，因为 select 会改写集合。nfds 为最大被监视 fd 加 1，超时参数与错误返回也需要处理，fd 必须满足 FD_SETSIZE 范围约束。
- **服务端流程：** 监听 fd 就绪后 accept，将新连接加入集合；连接 fd 就绪后 recv，区分数据、EOF 和错误；断连后 close 并移出集合。select 只报告就绪，不替代收发，也不保证整条消息到达。

## 暴露的问题与路线纠正

1. **select 可以用于客户端，但当前教学主线应优先服务端。** 客户端示例本身合法；当前目标是从多进程模型过渡到一个事件循环管理多个连接，先写多客户端 Echo Server 更符合课程与学习位置。此前先展开客户端的教学安排应纠正，不能把它说成 select 只能用于服务端。
2. **用户技术决策若有明显问题必须主动纠正。** 技术判断、学习路线、实现方案和工具选择都需要审查；不能因为学习者提出方案就默认正确，方向性问题必须在编码/实施前说明理由和替代方案。已写入 [TEACHING_PROTOCOL.md](../TEACHING_PROTOCOL.md)。
3. 教材作为主线，技术语义仍按 Linux/POSIX 查证：应用层整数不会由 TCP 自动转换字节序，不能直接把本机结构体当作跨平台协议；示例中的单次 send/recv 不代表完整收发。
