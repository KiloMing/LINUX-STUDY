## 今日学习内容

### 1. 7.4.1：向 AMCL 发布初始位姿

AMCL 在已有地图上定位时，需要先知道机器人在 `map` 坐标系中的大致初始位置。初始位姿不是速度命令，也不是导航目标，而是给定位系统的先验估计，常通过 RViz 的 **2D Pose Estimate** 或 `/initialpose` 发布。

消息的核心结构是：

```text
geometry_msgs/msg/PoseWithCovarianceStamped
├── header.frame_id = "map"
├── pose.pose.position      # x / y / z
├── pose.pose.orientation   # quaternion x / y / z / w
└── pose.covariance         # 初始估计的不确定性
```

初始朝向不能把角度直接写进 quaternion 的 `z`。平面机器人通常保持 roll、pitch 为 0，只把 yaw 转成四元数：

```cpp
tf2::Quaternion q;
q.setRPY(0.0, 0.0, yaw_rad);
msg.pose.pose.orientation = tf2::toMsg(q);
```

发布时还要注意 `/initialpose` 的订阅者和 QoS。若程序启动后只发布一次，应确认 AMCL 已经启动并能收到该消息；实际状态仍以 AMCL 输出、TF 和 RViz 中定位结果为准，不能只凭 publisher 进程存在判断定位成功。

### 2. 四元数与 yaw 的双向转换

今天把同一个知识点在三个任务里串了起来：

| 场景 | 转换方向 | 用途 |
|---|---|---|
| 7.4.1 初始定位 | yaw → quaternion | 构造 `/initialpose` 的朝向 |
| 7.4.2 查询位姿 | quaternion → roll/pitch/yaw | 把 TF 朝向转换为可读角度 |
| 7.4.3 单点导航 | yaw → quaternion | 构造导航目标 `PoseStamped` 的朝向 |

角度必须先转换为弧度：

```text
yaw_rad = yaw_degree × π / 180
90° = π / 2 rad
```

读取 TF 四元数时，可用 `tf2::Matrix3x3(quaternion).getRPY(roll, pitch, yaw)`。yaw 的输出默认是弧度；如果要显示角度，再乘 `180 / π`。四元数避免了直接用欧拉角表达旋转时的部分问题，但日志展示和二维导航仍常把最终方向解释为 yaw。

### 3. 7.4.2：通过 TF 查询机器人实时位姿

已完成 C++ TF listener 的实际运行，周期查询 `map` 与机器人底盘坐标系之间的变换，并输出：

```text
x / y / z
roll / pitch / yaw
```

实际截图中，机器人静止时输出稳定在约：

```text
x = -3.484, y = 2.12, z = 0.00, yaw = 0.90 rad
```

移动后，输出连续变化，例如：

```text
x:   -3.312 → ... → -2.688
y:    2.30  → ... →  2.75
yaw:  0.72  → ... →  0.54 rad
```

这说明查询节点能持续取得实时位姿，7.4.2 的课程实验已经跑通。实现结构包括 `tf2_ros::Buffer`、`tf2_ros::TransformListener`、定时器、`lookupTransform()`、四元数转 RPY，以及捕获 `tf2::TransformException`。查询时要特别注意 target/source frame 的顺序；“想得到机器人在 `map` 中的位姿”不能只靠变量名猜测，必须结合 `lookupTransform(target, source, time)` 的语义和实际输出验证。

### 4. 7.4.3：查看 `NavigateToPose` Action 接口

单点导航不是瞬时的一问一答，因此 Nav2 使用 Action：

```text
Goal：发送目标位姿
Feedback：导航过程中持续返回当前位置、剩余距离等信息
Result：最终成功、取消或失败
```

今天使用的关键命令是：

```bash
ros2 action list
ros2 action info /navigate_to_pose
ros2 interface show nav2_msgs/action/NavigateToPose
```

本机 Jazzy 接口截图确认的核心字段为：

```text
# Goal
geometry_msgs/PoseStamped pose
string behavior_tree
---
# Result
uint16 error_code
string error_msg
---
# Feedback
geometry_msgs/PoseStamped current_pose
...
```

接口字段可能随 Nav2 版本变化，编写代码时必须以当前环境中 `ros2 interface show` 的输出为准。`pose.header.frame_id` 应设置为 `map`；`behavior_tree` 当前可留空以使用默认行为树。目标点必须选在地图自由区域，不能机械照抄示例坐标。

### 5. C++ Action Client 已开始实现

`action_client.cpp` 已加入以下头文件并开始定义节点类：

```cpp
#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"
#include "nav2_msgs/action/navigate_to_pose.hpp"
```

当前需要先建立两个类型别名：

```cpp
using NavigateToPose = nav2_msgs::action::NavigateToPose;
using GoalHandleNavigateToPose =
    rclcpp_action::ClientGoalHandle<NavigateToPose>;
```

然后成员类型才可以写成：

```cpp
rclcpp_action::Client<NavigateToPose>::SharedPtr action_client_;
```

下一阶段的完整结构是：

```text
create_client<NavigateToPose>()
        ↓
等待 /navigate_to_pose Action Server
        ↓
构造 NavigateToPose::Goal / PoseStamped
        ↓
配置 goal_response / feedback / result 三个回调
        ↓
async_send_goal()
```

目标被接受只表示 Nav2 接收了任务，不等于导航已经成功；最终状态要在 result callback 中区分 `SUCCEEDED`、`ABORTED` 和 `CANCELED`。
