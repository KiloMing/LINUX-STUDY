## TCP 和两个 fd

TCP 是面向连接、可靠、有序的字节流协议。通信前要建立连接；TCP 通过确认、重传等机制提供可靠、有序的传输，但连接仍可能失败，程序要处理错误。字节流没有消息边界：一次 write 的内容不一定由一次 read 完整读到。

在服务端代码里，`server_fd` 是监听 socket，用来等待新连接；`accept()` 返回的 `client_fd` 是已连接 socket，用来和这一个客户端读写。变量名只是约定，职责由 socket 的状态和调用决定。关闭这次连接的 `client_fd` 后，`server_fd` 仍可继续接收新连接。

服务端的基本流程：

```text
socket → bind → listen → accept → read/write → close(client_fd)
                            ↑ 下一次 accept
服务结束时 close(server_fd)
```

`socket()` 创建 socket，`bind()` 绑定本地地址和端口，`listen()` 开始监听，`accept()` 取出一个连接并返回新的 fd。客户端通常是 `socket → connect → read/write → close`。后续写代码时要检查返回值，处理短读写；`read()` 返回 0 表示对端有序关闭了发送方向。

## IPv4 地址怎么填

- `sockaddr_in` 保存 IPv4 socket 地址，常用字段是 `sin_family`、`sin_port`、`sin_addr`；`sin_family` 填 `AF_INET`。
- `htons(8080)` 把端口从主机字节序转成网络字节序。`sin_port` 中存的是转换后的值，不能直接当作主机序整数读。
- `inet_pton(AF_INET, "10.211.55.4", &addr.sin_addr)` 把文本 IPv4 地址转成二进制网络地址，返回 1 才表示转换成功。
- 服务端绑定时，`addr.sin_addr.s_addr = htonl(INADDR_ANY)` 表示绑定所有本地 IPv4 接口，对应 `0.0.0.0`，不是某一台远程主机的地址。

## getaddrinfo 和内存生命周期

`getaddrinfo()` 根据主机名、服务名或端口字符串生成候选 socket 地址。现在先分清筛选条件和返回结果：

| 名称 | 当前理解 |
|---|---|
| `addrinfo` | 描述一个候选地址的结构，也用于填写查询条件 |
| `hints` | 调用者提供的筛选条件，先用 `{}` 清零 |
| `result` | 指向返回链表首节点的指针；先初始化为 `nullptr`，通过 `&result` 接收结果 |
| `ai_family` | 地址族，如 `AF_INET`；`AF_UNSPEC` 可允许 IPv4/IPv6 候选 |
| `ai_socktype` | socket 类型，TCP 示例使用 `SOCK_STREAM` |
| `ai_addr` | 通用地址指针 `sockaddr*`，交给 bind/connect |
| `ai_addrlen` | `ai_addr` 所指地址结构的长度，与地址一起传入 |
| `ai_next` | 下一个候选节点，最后一个为 `nullptr` |

先检查 `getaddrinfo()` 返回值，0 表示成功。不能假设第一个地址一定可用：用单独的指针从 `result` 开始沿 `ai_next` 遍历，按候选的 `ai_family`、`ai_socktype`、`ai_protocol` 创建 socket，再尝试 connect（客户端）或 bind（服务端）。失败时关闭这次创建的 fd，再试下一个；保留链表头用于释放。

今天重点弄清了这段：

```cpp
sockaddr_in server_addr =
    *reinterpret_cast<sockaddr_in*>(result->ai_addr);
freeaddrinfo(result);
result = nullptr;
```

前提是查询成功、结果有效，而且这个候选确实是 IPv4（如 hints 限定了 `AF_INET`）。类型转换本身没有复制数据，解引用后初始化 `server_addr` 才复制了 IPv4 地址结构，所以这份副本在释放链表后仍可使用。若只是保存 `ai_addr` 指针，释放后就不能再用；IPv6 候选也不能直接按 `sockaddr_in` 解释。

`freeaddrinfo(result)` 释放 getaddrinfo 分配的整个结果链表及其关联地址内存，不能用 `delete` 或直接 `free(result)` 代替。释放后不能再访问原节点、`ai_addr` 或 `ai_next`。它不会关闭 socket，也不会断开已建立的 TCP 连接；fd 仍需单独 `close()`。

## 网卡地址、监听地址和防火墙

本次看到的 `ifconfig` 中，`enp0s5` 的 IPv4 地址是 `10.211.55.4`，是该网卡在当前网络中的私有地址；其他设备能否访问还取决于网络和虚拟机配置。`lo` 是回环接口，`127.0.0.1` 表示当前这台系统自己。在宿主机访问 127.0.0.1，不是在访问虚拟机。

`0.0.0.0:8080` 表示程序监听所有本地 IPv4 接口的 8080 端口；只绑定 `127.0.0.1:8080` 则只接受本机回环访问。客户端连接时应使用具体可达地址，例如 `10.211.55.4:8080`。

防火墙中的 `8080/tcp` 指 TCP 8080 端口的规则。允许这个端口的流量，不会自动启动服务器，也不会替程序 bind/listen；程序监听了 0.0.0.0，也不代表防火墙已放行或外部网络一定可达。今天记录的是这几层的区别，不是已完成防火墙配置或外部连通验证。
