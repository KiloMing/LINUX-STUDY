- `main()` 创建 Node 并 `rclcpp::spin(node)`，由 Executor 调度 callback；Timer 事件与收到 Topic 消息是不同触发源。
- 先用独立 `cycle_demo` 和 `cycle_subscription` 练发布/订阅，再在一个 `CycleContarl` Node 内同时持有 Publisher 与 Subscription。收到 Pose 后计算误差、发布 Twist，再由新的 Pose 提供反馈。

### 闭环控制模型与当前快照

目标点为 `(1.0, 1.0)`，`k_dis = 1.0`、`k_ang = 1.0`，声明 `max_speed_ = 3.0`。

```text
Pose(x, y, theta)
  → error_x = target_x - x，error_y = target_y - y
  → error_dis = sqrt(error_x² + error_y²)
  → target_angle = atan2(error_y, error_x)
  → error_ang = target_angle - theta，归一化到 [-pi, pi]
  → P 控制计算速度 → 发布 Twist → 新的 Pose
```

`atan2(y, x)` 根据两个坐标分量确定目标方向；角度有周期性，归一化用于选择最短转向。例如从 +179° 到 -179°，原差 -358° 应归一化为 +2°。P 控制为 `u = Kp * error`，距离和角度可用不同系数；这不是完整 PID，未实现 I/D。`kp` 是参数，距离/角度计算以后可封装，当前先把 callback 流程写清楚。

## 暴露的问题

1. 当前写的是 `cmd_vel.linear.y = k_ang * error_ang`。turtlesim 转向应使用 `cmd_vel.angular.z`；这是明天第一项修正。
2. `max_speed_` 只有声明，未实际用于限幅；不能记录为已完成速度限制。
3. `target_ang_` 每次由当前误差重新计算，可改为 callback 局部变量。
4. 快照没有显式包含 `<cmath>`；需确认 `std::sqrt`、`std::atan2` 的声明及 `M_PI` 可用性。`M_PI` 不是标准 C++ 保证的宏，必要时使用明确的 pi 常量。
5. 合并节点的 CMake target、依赖、安装及真实 executable 名需在实际工程再次核对。`current_theta` 已声明但计算直接用了 `msg->theta`，可随后统一。
6. 尚无到点停止阈值或目标附近稳定性证据；不能把“公式已经写出”当成已经能到达目标。
