## 做过的代码或实验

### 1. turtlesim Topic 闭环控制

订阅 `/turtle1/pose` 获取当前位置与朝向，发布 `/turtle1/cmd_vel` 控制运动。学习的计算顺序是：

1. 计算目标与当前位置的 `dx`、`dy`，距离为 `sqrt(dx*dx + dy*dy)`。
2. 用 `atan2(dy, dx)` 计算目标方向；角度误差为目标角减当前 `theta`。
3. 将角度误差归一化到 `[-pi, pi]`，避免跨越正负 pi 时绕远路。
4. 使用角度阈值决定先转向还是允许前进；距离比例控制让线速度随距离减小。
5. 限制最大速度；转向命令对应 `angular.z`，前进对应 `linear.x`。

9 月 25 日保存的 `CycleContarl` 是未验证旧草稿，含 `linear.y` 转向错误和未使用的最大速度变量。今天学习内容已推进到阈值与限幅，但本次没有取得最终控制源码、到点日志或独立运行结果，因此保留旧快照的 UNVERIFIED 标记，不把建议当成已核验修复。下一次需补到点停止、角度跨界与限幅效果的实际证据。

### 5. sys_status_display 与线程模型

订阅 `/sys_status`，接收 `SystemStatus` 后用 `std::stringstream` 组装文本，再转换为 `QString`，通过 `QLabel` 显示。学习对话记录了主机名、CPU、内存总量/可用量及网络收发数据的窗口显示结果。

```text
进程 1：status_publisher → ROS2 Topic
进程 2：status_display
         ├── 主线程：app.exec()，处理 GUI 事件
         └── std::thread：rclcpp::spin(node)，处理 ROS2 回调
```

两个进程通常各有独立地址空间，通过 ROS2 通信；同一进程的线程共享地址空间，访问共享对象时仍须考虑同步和生命周期。这里理解的是线程共享内存，不等于已使用 ROS2 共享内存传输。

Qt GUI 更新应在主线程进行。对话中的学习版曾从 ROS2 子线程直接更新 `QLabel`；即使当时显示正常，也不能认定这种跨线程访问安全。后续应通过排队的 signal/slot 等方式把更新交回 GUI 线程，并核验退出时 ROS2 停止、线程 join 和对象销毁顺序；本次未声称已完成这些改造。

### 6. Service 入门与当前断点

```text
Client ── Request ──> Server
Client <─ Response ── Server
```

用 `/spawn` 的概念例子理解：请求创建一只海龟，服务端处理后返回结果。Topic 的“持续广播”是当前帮助区分通信用途的说法，不表示 Topic 必须不停发送，也不把它等同于底层网络广播。
