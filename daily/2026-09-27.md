## 做过的代码或实验

### 1. Python 自定义人脸检测 Service：4.2.1～4.2.4

接口包为 `demo_interfaces`，接口为 `srv/FaceDetector.srv`：Request 携带 `sensor_msgs/Image image`；Response 包含 `number`、`use_time` 和 `top/right/bottom/left` 坐标数组。当前记录不补造尚未核验的响应字段类型。

```text
Client：读取 resource/default.png → CvBridge.cv2_to_imgmsg(bgr8)
  → FaceDetector.Request → /face_detect
Server：CvBridge.imgmsg_to_cv2 → face_recognition.face_locations
  → 人脸数、检测耗时、坐标数组 → return response
Client：future.result() → 读取 Response → cv2.rectangle → 显示绘框结果
```

- Server 用 `create_service(FaceDetector, '/face_detect', callback)`，通过 `rclpy.spin(node)` 持续处理请求；检测使用 `hog` 示例，逐个填充坐标数组。
- Client 用 `create_client`、`wait_for_service`、`call_async`；一次请求模式先调用 `send_request()`，内部用 `spin_until_future_complete(self, future)` 驱动事件直至结果返回，再读取 `future.result()`。
- 检测发生在 Server，Client 只发图和使用返回结果；画框时两点是 `(left, top)` 和 `(right, bottom)`。
- `setup.py` 的 `console_scripts` 注册 `face_detect_node`、`face_detect_client_node`；图片需随资源安装，用 `get_package_share_directory` 定位。
- 学习者反馈“OK，成功”；历史对话文字记录 Server 的 `Image received`、Client 的 `test face number: 1`、约 `0.202s` 和蓝色人脸框。耗时是当次记录，不作为性能结论。

### 2. C++ Patrol 自定义接口：4.3.1

沿用 `demo_interfaces`，新增：

```text
float32 target_x
float32 target_y
---
int8 SUCCESS = 1
int8 FAIL = 0
int8 result
```

`---` 分隔请求/响应；SUCCESS、FAIL 是常量，`result` 是返回字段。将 `srv/Patrol.srv` 加入 `rosidl_generate_interfaces`，保留 FaceDetector 所需的 `sensor_msgs` 依赖。C++ 使用生成的 `demo_interfaces/srv/patrol.hpp`，不能直接 include `.srv`。

### 3. C++ Server 与控制器：4.3.2

`demo_cpp_service` 中的 `TurtleController` 保存 `rclcpp::Service<Patrol>::SharedPtr`，用 `create_service<Patrol>` 接收请求，检查坐标后更新成员 `target_x_ / target_y_`，返回 SUCCESS 或 FAIL。

```text
/patrol 请求 → 校验目标 → 更新 target_x_ / target_y_ → 返回接受结果
/turtle1/pose → 位置/角度误差 → 原有控制算法 → /turtle1/cmd_vel
```

Service、Subscriber、Publisher 是构造函数内平级创建的成员。目标必须跨回调保存，不能只放在 Service 回调的局部变量里。控制部分复用 atan2、角度归一化、距离比例控制、转向阈值及最大速度限制。

命令行调用后学习者确认“确实，已经进行移动”。**SUCCESS 表示目标已被接受，不表示已经到达目标**；到点停止、边界合法性、限幅和角度跨界仍需专门验收。9 月 25 日旧草稿的 UNVERIFIED 状态继续保留，不用新对话覆盖旧文件。

### 4. C++ 异步 Client：4.3.3

- `create_client<Patrol>("patrol")` 创建客户端；`create_wall_timer(10s, ...)` 周期触发，Timer 句柄作为成员保存。
- 回调先用 `wait_for_service(1s)` 等服务，并检查 `rclcpp::ok()`；创建 `std::make_shared<Patrol::Request>()`，填入 `(8.0, 3.0)`。
- `async_send_request(request, callback)` 发出请求；响应回调的参数为 `rclcpp::Client<Patrol>::SharedFuture`，`future.get()` 取得响应共享指针，再判断 `response->result`。
- `rclcpp::spin(node)` 持续处理 Timer 与响应事件；发送后回调返回，结果到达再执行响应 lambda，不需要在此响应模式中再嵌套 `spin_until_future_complete`。
- 示例中等待服务的 while 循环仍会阻塞当前 Timer 回调；不能把整个流程描述成完全无阻塞。服务长期不可用、请求超时与重复请求处理留待变式验证。


## 暴露的问题

| 现象/错误 | 修正与边界 |
|---|---|
| `ModuleNotFoundError: face_recognition` 再次出现 | 检查是否退出 `.venv`；核对 `which python3`、实际 import 和安装入口首行；在已激活环境用 `python3 -m colcon build` 重建后 source。仅激活环境不保证旧入口解释器已改变 |
| `CvBridge` / `get_package_share_directory` 未定义 | Client 自己导入 `from cv_bridge import CvBridge`、`from ament_index_python.packages import get_package_share_directory` 和 `import cv2`；Server 的 import 不会传给 Client |
| Server/Client 都启动却无结果 | 一次请求 Client 把 `spin()` 写在 `send_request()` 前，后者正常运行期间无法执行；改为先主动请求，内部 spin_until_future_complete。用“进入函数→发现服务→发送→收到响应”日志定位 |
| `self.clent`、`response.bottom.append()`、多余 `}` | 改为 `self.client`、`append(bottom)`，删除多余括号并核对缩进；可用 `python3 -m py_compile` 检查语法 |
| FastDDS `RTPS_TRANSPORT_SHM Error` / `open_and_lock_file failed` | 当天存在警告但最终服务与绘框跑通，未阻断主线；先验证服务发现和响应。未确认根因，也未记录为已修复，不把所有通信失败都归因于 SHM |
| 接口生成 `overriding recipe` / `ignoring old recipe` | 对话提示检查 FaceDetector 是否在 rosidl 生成列表重复登记；后续接口运行成功，但未归档最终 CMake，不将重复登记推测写成已核验根因 |
| `--build-type ament-cmake` | 改为 `ament_cmake` |
| include `Patrol.srv` / `Patrol.hpp` | 使用生成的 `demo_interfaces/srv/patrol.hpp`；先生成接口，再配置 target 依赖 |
| `FALL`、response 变量名不一致、lambda 括号错位 | 改为 `FAIL`，统一回调参数名；正确闭合 `create_service(...);`，三个通信对象平级创建 |
| `Patol`、`thie/thiss`、`getlogger`、`!rclcpp::ok` | 统一 `Patrol`、`this`、`get_logger()`、`!rclcpp::ok()`；补 `<chrono>` 与 `std::chrono_literals`；修正 `rclcpp::init(argc, argv)`、`rclcpp::shutdown()` 及结尾分号 |
| `y=%.f` | 合法格式但显示精度不合预期，统一 `%.2f`，不误记为编译错误 |
| 编译成功但 VSCode 自定义接口飘红 | 区分 IntelliSense 与编译器依赖；当天 build 成功，编辑器需配置实际生成头文件的 include root |

对话确认的头文件位置与 includePath：

```text
文件：/home/kiloming/my_ros/chapt2_ws/install/demo_interfaces/include/demo_interfaces/demo_interfaces/srv/patrol.hpp
```
