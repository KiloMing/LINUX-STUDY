### ROS2 Node 与 Topic

- Node 是 ROS2 的逻辑运行/通信单元，不等于 Linux 进程；一个进程可以包含多个 Node。节点可通过 Topic、Service、Action 等机制通信。
- Topic 初步模型是 `Publisher → Topic → Subscriber`，即命名的异步发布/订阅通道。Topic 名称不是进程，也不表示每条消息必然成功交付；具体通信行为后续结合消息类型和 QoS 验证。
- 今天只讨论概念，尚未完成 Publisher/Timer/Topic 的完整 ROS2 实现，也没有 topic/service/action 的运行证据。

### C++ Lambda、std::function 与 const 引用

Lambda 基本语法：

```cpp
[capture](args) -> return_type { ... }
```

- `->` 在这里引出返回类型，通常可在能够推导时省略，不是成员访问运算。
- 值捕获如 `[x]` 保存外部变量的副本；引用捕获如 `[&x]` 引用原变量，原变量必须在使用时仍存活。`[=]` / `[&]` 表示默认值捕获 / 引用捕获方式。
- `[this]` 捕获当前对象的指针，便于访问成员，不会复制整个对象，也不会自动延长对象生命周期。
- 捕获提供“创建 Lambda 时带入的外部状态”；参数提供“调用 Lambda 时传入的数据”。两者来源与时机不同。
- `std::function<返回类型(参数...)>` 是可调用对象包装器，可保存签名兼容的 Lambda、普通函数等。例如 `std::function<void(const std::string&, const std::string&)>` 表示接收两个字符串常量引用、无返回值的可调用对象。
- Lambda 是提供实现的一种方式；callback 是“交给另一段代码在适当时机调用”的角色；std::function 可作为传递/保存 callback 的类型。它们本身都不自动创建线程。
- `const std::string&` 通过引用避免传参时复制字符串，并限制通过该引用修改字符串；它不拥有字符串，也不自动延长异步使用时的数据寿命。

### cpp-httplib 与下载 callback

- cpp-httplib 同时封装 HTTP Client 和 Server，是底层 socket/HTTP 操作之上的高层接口，不是 ROS2 通信机制本身。
- 客户端流程：`httplib::Client client(host)` → `client.Get(path)` → 检查 response 是否存在，再检查 `response->status`，读取 `response->body`。收到响应不等于 HTTP 状态成功；示例可按 `status == 200` 判断成功。
- 服务端流程：创建 `httplib::Server`，用 `Get(path, handler)` 注册 GET 路由处理器，再用 `listen(host, port)` 监听。服务端的 `Get` 是注册处理逻辑，客户端的 `Get` 是发起请求。
- 今日讨论的下载接口形状是 `download(host, path, const std::function<void(const std::string&, const std::string&)>& cb)`。成功后调用 `cb(path, response->body)`，把路径和正文作为两个参数交给调用者处理；不是 `cb(path/body)` 的除法表达式。
- 下载函数负责获取数据，callback 负责决定拿到数据后如何处理；传入 callback 的 const 引用可避免接口处复制包装器，但不保证该包装器在异步执行时仍存在。
- `start_download` 可能创建线程并异步执行下载，但必须查看实际源码才能确认。同步 `client.Get()` 即使放在线程里仍会阻塞该工作线程；异步性来自外层调度。

### CMake 头文件路径

当前对话描述的 package 结构类似：

```text
demo_cpp_pkg/
├── include/cpp-httplib/httplib.h
├── src/download_file.cpp
└── CMakeLists.txt
```

视频与当前写法的配套关系：

| 编译器 include 搜索起点 | C++ include 写法 | 拼接后的文件 |
|---|---|---|
| `include` | `#include "cpp-httplib/httplib.h"` | `include/cpp-httplib/httplib.h` |
| `include/cpp-httplib` | `#include <httplib.h>` | `include/cpp-httplib/httplib.h` |

- 视频的 `include_directories(include)` 与 `#include "cpp-httplib/httplib.h"` 配套。若当前只添加 `include`，却写 `#include <httplib.h>`，该搜索起点下会寻找 `include/httplib.h`，少了中间目录；搜索不会自动递归到子目录。
- 对当前 `<httplib.h>` 写法，可在创建 target 后设置 `target_include_directories(download_file PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/include/cpp-httplib)`。实际 target 名需以工程为准；另一种方式是保留视频配置并改 include 中的相对路径。
- 当前修改的是 **CMakeLists.txt，不是 Makefile**；CMake 可生成 Makefile 等构建系统文件。
- `include_directories()` / `target_include_directories()` 设置头文件搜索目录；`find_package()` 查找并加载包的配置或查找模块，不会因为把仓库复制进 `include/` 就自动找到该包。它也不只限于“系统已安装包”，可使用配置好的其他搜索前缀或构建目录。
- 仅以本地头文件方式使用时，不应把添加 `find_package(httplib REQUIRED)` 或把 httplib 写进 `ament_target_dependencies()` 当成修复路径的必要步骤；是否使用包 target 取决于实际集成方式。找到头文件也不代表所有编译/链接依赖都已满足。

### 多线程与回调的边界

多进程通信本身不要求 callback；回调是事件驱动框架常用的组织方式，可以同步调用，也可以由其他线程调用。后续再结合实际 `start_download` 学习 `std::thread`、`join()`、mutex 和共享数据保护：谁创建线程、谁等待结束、callback 在哪个线程执行、引用和 `[this]` 的对象何时销毁，都需逐项确认。
