## 一、8.1 pluginlib

学习链路为：`Shape` 抽象类定义接口 → `Square` / `Triangle` 派生类实现 → 编译共享库 → 导出与 XML/CMake 注册 → `ClassLoader` 动态加载 → 通过基类指针调用。

- **Shape：** 用纯虚函数约定接口；通过基类指针使用派生对象涉及多态，基类应提供虚析构函数。
- **Square / Triangle：** 按基类的精确签名实现 `area() const`，用 `override` 让编译器检查重写关系。
- **PLUGINLIB_EXPORT_CLASS：** 导出具体派生类与其基类的插件关系。
- **plugins.xml：** 描述插件库、类类型和基类类型；名称必须与实际命名空间、类名和库对应。
- **CMake 注册：** 通过 `pluginlib_export_plugin_description_file()` 注册描述文件；共享库、头文件安装及目标依赖同样需要正确配置。
- **ClassLoader：** 根据插件描述查找并加载类型，`createSharedInstance()` 创建共享指针管理的插件实例，再通过基类接口调用。加载器和实例的生命周期也需要配合。

## 三、8.2 Nav2 规划器职责与接口

Planner Server 管理规划任务和规划器插件；`nav2_core::GlobalPlanner` 规定规划器接口，具体插件生成路径。Controller 负责跟踪路径并计算运动控制指令。

`nav_msgs/msg/Path` 表达带有头信息的一组位姿，是路径；`geometry_msgs/msg/Twist` 表达线速度和角速度，是速度指令。生成 Path 并不等于机器人已经开始行驶或完成导航。

课堂使用的五个接口：

| 接口 | 职责 |
|---|---|
| configure() | 获取节点、参数、TF 和 costmap 等资源并初始化 |
| activate() | 激活阶段所需操作 |
| deactivate() | 停用阶段所需操作 |
| cleanup() | 清理配置阶段获取的资源 |
| createPlan() | 根据起点和终点生成路径 |

前四项是生命周期相关接口，`createPlan()` 是规划接口；具体函数签名应以实际安装的 Nav2 头文件为准。

## 四、WeakPtr 与 SharedPtr

`shared_ptr` 表示共享所有权；最后一个共享所有者释放后，对象才销毁。`weak_ptr` 不拥有对象，也不会增加强引用计数，不能直接解引用。

课堂中的 `parent.lock()` 尝试取得一个 `shared_ptr`：对象仍存活时返回有效指针，已经销毁时返回空指针，使用前应检查。这里的 `lock()` 是获取共享所有权，不是互斥锁操作。

插件通过弱引用接收父节点，有助于避免双方长期强引用形成所有权环。但如果把 `lock()` 的结果长期保存为 `node_`，仍会延长父节点生命周期，必须结合所有权关系和 `cleanup()` 释放策略判断；不能认为传入 WeakPtr 就自动消除了所有循环引用。

## 六、8.2.3 createPlan 直线插值

讲解的几何思路：起点 `(xs, ys)`、终点 `(xg, yg)`，距离 `d = sqrt((xg-xs)^2 + (yg-ys)^2)`。分为 N 段，令 `t = i/N`，用 `x = xs + t(xg-xs)`、`y = ys + t(yg-ys)` 生成沿线位姿；包含两端时共有 N+1 个点。

后续实现核验应检查浮点除法、插值间距为正、起终点重合时避免除零、路径首尾点、坐标系/时间戳和有效朝向。直线插值本身不提供避障能力；穿越障碍物的路径不能当作有效导航结果。碰撞检查及不可达情况处理仍需要实际实现与测试。

上述公式是算法学习记录，并非已提交或已验证的 `createPlan()` 实现；Gazebo/Nav2 加载和联调尚未确认。
