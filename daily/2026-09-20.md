## 今日学习内容

### poll

- 使用 `pollfd[]` 管理监听 fd 与多个连接 fd。
- 空槽位使用 `fd = -1`；`poll()` 会忽略负 fd 项。
- `events` 由程序设置，表示希望监控的事件；`revents` 由 `poll()` 返回，表示实际发生的事件。
- `server_sock` 负责监听新连接；`accept()` 每成功一次会返回一个新的 `client_sock`，一个监听 socket 可以对应多个连接 socket。
- 外层遍历用于找“哪些 fd 就绪”；收到新连接后内层遍历用于找 `fd == -1` 的空槽，两次遍历目的不同。
- `poll()` 只报告“现在至少可以读一次”，不保证 TCP 中想要的 10 字节已经全部到达；完整固定长度消息仍要由应用层循环累计。
- 学习版代码中修正了未初始化 `pollfd[]` 与 `poll(fds, 10, -1)` / 1024 槽位扫描范围不一致的问题。

### socket / client_sock 关系复盘

- `server_sock` 是监听 socket，用于 `bind/listen/accept`。
- 客户端程序也有自己的 socket；服务端 `accept()` 返回的 `client_sock` 才是服务端这一侧针对某条 TCP 连接的通信 fd。
- 服务端通常形成一对多关系：一个 `server_sock`，多个 `client_sock`。
- 在多路复用循环里必须区分监听 fd 与连接 fd：监听 fd 就绪时调用 `accept()`，连接 fd 就绪时调用 `read()/recv()`。

### epoll LT

- 开始学习 `epoll_create1() → epoll_ctl() → epoll_wait()` 主模型。
- `epfd` 是 epoll 实例的 fd，不是客户端连接 fd。
- `epoll_ctl()` 用 ADD/MOD/DEL 管理 interest list。
- 新客户端通过 `accept()` 得到 `client_sock` 后，仍需显式 `EPOLL_CTL_ADD` 才会被 epoll 监控。
- `epoll_wait()` 返回的是本轮已就绪事件；循环范围应使用 `0 .. ready-1`，不是扫描全部已注册 fd。
- 事件循环仍需判断 `events[i].data.fd == server_sock`：监听 fd 的 `EPOLLIN` 对应新连接，普通连接 fd 的 `EPOLLIN` 对应可读数据。
- 当前先按 LT 学习；非阻塞 + ET、`EAGAIN/EWOULDBLOCK` 留在下一阶段。
