# 视觉巡航教学计划与实施流程

制定日期：2026-10-11。前置状态：激光雷达 SLAM + Nav2 仿真已跑通，第八章结束。以下是下一阶段教学计划，尚未实施验收。第九至十五章为本项目后续教学编号，不代表原课程官方目录。

## 一、最终需要完成什么

完成一套能够从 Gazebo 迁移到真实小车的巡航系统：

**RGB-D 采集 → 建图与定位 → Nav2 导航 → 多点巡航 → 到点拍照 → 异常处理与任务记录。**

第一版目标：提前建好地图，机器人重启后完成视觉定位，沿 A/B/C/D 巡航，到点拍照，遇到障碍能够处理，并保存任务结果。自主探索未知区域建图放到后续扩展。

最终交付包含：工程源码、启动文件、参数配置、地图、巡航点配置、运行日志和部署说明。

课程按验收结果推进。每课建议安排 2～3 小时，排错较多时拆成两次；下面的课次是学习单元，不是固定完成期限。

## 三、每堂课怎么教

固定采用下面的流程，避免一次堆入过多新内容。

1. **回顾与预测，10 分钟**：先解释上节的数据流，再预测本次修改会影响哪些话题、TF 或节点。
2. **必要原理，20～30 分钟**：只讲本次实验需要的概念。例如第一课解释深度图和 CameraInfo，不展开完整视觉 SLAM 数学推导。
3. **最小实验，60～90 分钟**：一次打通一条链路。先显示深度，再接建图；先单点导航，再做巡航。
4. **独立变式，20～30 分钟**：自己调整相机位姿、增加巡航点或改变障碍位置，并解释结果。
5. **验收与记录，15 分钟**：保存配置、关键输出和失败原因，更新 daily 与 CURRENT。只有获得独立复现证据后才调整 MASTERY。

教学时先给目标和必要提示，由学习者完成关键修改；遇到问题沿数据流排查，再补充解释和参考实现。

## 四、系统实际运行流程

**首次建图：**

启动底盘与相机 → 检查数据和 TF → 启动 RTAB-Map 建图 → 低速遥控采集环境 → 检查地图与回环 → 保存数据库和二维地图。

**日常巡航：**

启动底盘与相机 → 加载地图与数据库 → 确认视觉定位有效 → 启动 Nav2 → 加载巡航点 → 开始巡航 → 到点执行拍照 → 保存结果。

**巡航任务状态：**

等待就绪 → 前往目标点 → 确认到达 → 拍照与记录 → 下一个点 → 完成本圈 → 下一圈或结束。

导航失败进入失败处理；用户取消进入取消与停车流程。定位丢失或关键传感器断流时，应停止继续派发目标，并执行已验证的停车策略。

## 五、巡航功能分四步实现

| 版本 | 功能范围 | 必须验证 |
|---|---|---|
| V1：单圈 | A → B → C → D，完成后结束 | 正确识别成功、失败和取消；最后一点得到处理 |
| V2：到点任务 | 每点保存当前图像和位姿，可复用语音播报 | 图像足够新；拍照失败单独记录，不混同导航失败 |
| V3：循环巡航 | 支持配置圈数，每圈重置任务状态 | 不重复发送目标、不重复拍照、不覆盖文件 |
| V4：异常处理 | 处理目标不可达、定位丢失、相机断流和用户取消 | 重试有上限；失败原因明确；取消后不再派发目标 |

到点事件必须依据明确的导航结果或路点任务执行机制，不能只凭 Feedback 索引变化推断成功。

建议照片按“任务编号／圈数／点位／时间”组织；每条任务记录至少包含目标点、开始和结束时间、导航结果、照片路径及错误原因。

## 六、阶段性验收标准

**仿真巡航验收**

- 完整重启后可以重新定位并开始任务。
- 连续三圈 A/B/C/D 巡航，逐点记录到达结果。
- 每个成功到达的点只保存一次有效照片。
- 加入临时障碍，记录停车、绕行或导航失败的实际行为。
- 测试不可达目标、取消任务和相机断流。
- 能从日志判断问题出在感知、定位、规划、控制还是巡航逻辑。

**真机巡航验收**

在仿真验收基础上，增加轮径/轮距与相机外参标定、失联停车、急停和实际停车距离测试。先以低速短路线验证，再扩展巡航范围。

位置误差、到点角度、允许耗时与停车响应时间，在对应实验开始前确定，并记录测量方法。

## 七、当前遗留问题怎么安排

- **A* 距障不足：** 作为规划器优化实验保留；视觉导航首次联调使用官方规划器建立基线。
- **速度时间戳与超时异常：** 仿真中继续定位，进入实体运动联调前必须查清。
- **Gemini Pro 驱动：** 放在相机独立阶段验证，先确认实际型号、RGB 接口和兼容驱动。
- **最终源码缺失：** 第一课先归档当前真正跑通的工程，确保后续能够回到基线。

## 八、第一课的具体安排

**课题：认识并检查现有小车的相机数据链路。**

本课先完成四件事：

1. 找到相机 Xacro/SDF、启动文件和桥接配置。
2. 判断现有相机是普通 RGB，还是已经提供深度数据。
3. 整理 RGB、Depth、CameraInfo、点云的话题、类型、频率与坐标系。
4. 画出从 Gazebo 传感器到 ROS2、再到 RViz 的数据流。

**本课交付：一张相机接口表、一份现有配置快照、一份缺失项清单。**

验收时能够回答：每条数据从哪里来、代表什么、使用哪个坐标系，以及为什么“有彩色画面”还不能证明 RGB-D 建图条件已经满足。
